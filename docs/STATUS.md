### UXA-01 — Request loop on EN/DE 404 pages (P0)

- **Cause:** Next.js 16's client router learns a route as a pattern when a URL maps one to one onto the rendered route.
  - The proxy rendered `/en/not-there` from the identical path through the catch-all `[locale]/[...rest]`. The router therefore predicted the catch-all for every `/en/…` and `/de/…` link whose slug differs from the Polish folder (`products` → `produkty`).
  - The head-only prefetches of those links are not checked against the server's tree and repeated without end, about 500 requests per second per tab. The loop continued on later pages of the session (e.g. after clicking Home).
  - PL was unaffected because its URLs carry no locale segment, so the client detects the rewrite.
- **Fix:** `src/proxy.ts` renders unknown paths under an internal segment (`/<locale>/unknown/<path>`), so the rendered path never mirrors the URL and the pattern is not learned.
  - The 404 page, its links, prefetching elsewhere, statuses and redirects are unchanged.
  - Regression test: `npm run test:notfound`.
- **Details:** [`architecture.md`](architecture.md), "Routing"; evidence in the verification table ("UXA-01 loop check").

Not needed while the site sets no non-essential cookies; must be built before any analytics (C-47, `security.md` §7). 3. **Dev dependency audit:** 5 high findings, all in lint tooling (`eslint-config-next` → `@next/eslint-plugin-next` → `fast-glob` → `micromatch` → `braces`). Production dependencies are clean. `npm audit fix --force` would make breaking changes; not applied.
4. **Source library absent.** `../source-assets` and `../research` are not next to this checkout, so `npm run assets`, `scripts/import-certificate-scans.mjs` and `scripts/build-privacy-drafts.mjs` cannot run here, and source facts cannot be re-checked here. `npm run assets` stops with `source-assets not found` before deleting anything. The hero video source `home_bottom.mp4` is also outside the repository (`asset-map.md`).
5. **History before 2026-10-09 is reconstructed.** All site work is in one commit, `b2fdc66` (2026-10-08). The branch `feature/mckeen-audit-fixes` named in older notes does not exist locally or on `origin`.
6. Five imported images are no longer referenced but are still in `public/` until the client confirms (see `asset-map.md`, "Imported but no longer referenced"; the former hero photo joined the list).
7. **Hero video weight and sharpness:** 9.54 MiB on desktop/tablet and 3.20 MiB on phones per first visit (then cached for 7 days); Save-Data and 2G/3G connections get the poster only. The source resolution limits sharpness on high-density and very large screens (C-63).
8. **Browser coverage:** automation used Edge/Chromium with responsive viewports; Firefox, Safari (autoplay, `getAutoplayPolicy`, `sessionStorage` in private mode, CSS `@property`, CSS masks incl. the embroidered bull with `vector-effect` strokes, `max()` in colours, scroll-driven animations and `timeline-scope`: without them the back-to-top tag stays hidden when JavaScript is off), physical mobile hardware (incl. the safe-area insets on notched phones) and an actual screen reader were not exercised.
9. **Selector reel during fast travel:** the red stitch marks cross the label rolling past (NAV-005 detail, cosmetic, only while moving).
10. **Console warning on 404 pages (development):** React reports "Encountered a script tag while rendering React component" on not-found pages (`/nie-ma-takiej-strony`, `/en/not-there`); found during the DESIGN-001 audit, not caused by it: it comes from the INTRO-001 inline script in `[locale]/layout.tsx`, which is rendered on the client there. Harmless (the intro only runs on the home page). `test:notfound` visits 404 pages on a production build only and checks runtime errors, not console warnings. Fix in a separate task (e.g. render the script in the document head or via `next/script`).
11. **`/favicon.ico` 404 when a PDF is shown:** a PDF has no icon link, so the browser asks for `/favicon.ico`, which does not exist (the site ships `icon.svg` only). It is visible since PDFs are linked (GAP-01) and is cosmetic: the PDF tab shows the default icon.
12. **Focus ring after A11Y-001 (2026-10-12):** the ring reaches 3:1 on every surface ("A11Y-001 checks"). Measured and left as they are:
    - the current drum tab at 1440 px: the carriage covers the left and right sides of its inset ring; the top and bottom (3 px, at least 3.8:1) stay visible;
    - in the scrolling enquiry dialog on phones Chrome does not scroll a field that is already partly visible (the message field), so the bottom of its ring can sit below the dialog's edge until the user scrolls;
    - the blue ring and the beef red have the same lightness: where a ring touches red (the selected Kontakt topic above the next one) that side has about 1.2:1, the other sides carry it; one Zakłady product link touches the tan "Produkte:" label on one side (2.5:1);
    - Firefox, Safari, Windows high contrast and real screen readers were not tested (Known issues 8).
13. **Home quality section, from 64rem:** the photo (5:4) ends at about half of the text column, because the two certificate cards make that column long. The empty area under the photo is 347–431 px at 1280–1920 px (PL/EN/DE) and 798 px at 1024 px, where the cards stack. Found in the stage 1.4 review; not changed.
14. **Trust strip at 700–899 px:** the four facts wrap as 3 + 1, so "3 zakłady…" stands alone in a second row (tablets in portrait). From 900 px it is one row of 4; below 700 px it is 2 + 2. Found in the stage 1.4 review; the trust strip is one of the parts the user froze, so a fix needs their consent.
15. **Photo sharpness on phones:**
    - The chain photos (1920 px sources) and the truck photo are cover-cropped into boxes far taller than the source ratio, but their `sizes` hints assume the box width ("34vw", "100vw"). On a 390 px phone (DPR 2) the browser loads 384 px files for the three chain tiles (about 2.5× enlarged) and an 828 px file for the truck (about 1.9×), so both look soft. The hero already uses ratio-aware `sizes`.
    - The product photos are limited by their sources (595–660 px wide) and look soft on high-density desktops. They are labelled illustrative (C-61).
    - Found in the stage 1.4 review; not changed.
16. **Rate-limit IP hash without `RATE_LIMIT_SALT` (privacy, low; reported in SECURITY-001, not changed).** `clientKey()` (`lib/security/request.ts`) hashes the client IP with `env.rateLimit.salt`, which falls back to the development salt in the public source (`lib/env.ts`) when the variable is missing.
    - **Impact:** whoever can read the rate-limit keys (process memory, or Redis for the window length) could recover IPv4 addresses by trying them all. The keys are not logged; the limit itself works.
    - **No longer affected:** the form result signature, which fails closed since SECURITY-001 (2026-10-11).
    - **Remedy:** set `RATE_LIMIT_SALT` (deployment checklist, [`security.md`](security.md) §10). Removing the fallback in code would need the user's decision.
