# Rebuild gap audit (2026-10-10)

Dated record of the read-only audit "FULL REBUILD GAP AUDIT" requested by the user on 2026-10-10. It compares the rebuilt site with the Phase 1 research of the legacy site. Priorities and classifications below are as assessed on that day.

- **Live status** of every finding (GAP-01 … GAP-27): [`STATUS.md`](STATUS.md), "Gap audit tracker".
- **Client questions** (C-xx) and their wording: [`client-confirmations.md`](client-confirmations.md). This file only records the audit's assessment of them.

## Scope and method

- **Compared:** the eight research documents `00-master-summary` … `07-open-questions` (crawl of mckeen-beef.eu on 2026-10-05; supplied by the user, kept outside the repository) with the uncommitted state of `codex/3d-drum-navbar`. Meaning was compared, not sentences.
- **Read-only:** no code, configuration, data or asset was changed, and the documentation was updated only after the user accepted the results.
- **Forms:** tested with synthetic data only, on a temporary local production server whose SMTP pointed at `127.0.0.1:9` (refused). Nothing was sent; the server was stopped afterwards.
- **Checks run on 2026-10-10:**
  - `npm run lint`, `npm test` (19/19), `npm run build`;
  - `npm run test:nav` (16/16, dev server);
  - `npm run test:home`: one failure on the dev server (GAP-24), passed on the local production build;
  - `npm run test:forms` 12/12 (`FORMS_EXPECT=fail`, local production server);
  - 18 additional synthetic form requests and 5 result pages;
  - `npm audit --omit=dev` (0) and `npm audit` (5 high, dev tooling);
  - an HTTP crawl of all 42 pages and their internal links;
  - 117 legacy URLs, 11 unknown URLs;
  - no-JS form and router checks;
  - horizontal overflow at 375/390 px on all 42 pages;
  - a lab performance snapshot;
  - the 2026 cutting-plant certificates read directly from the PDFs.
- **Not verifiable here:** `../source-assets` (page-text archive, originals) is absent, so statements that the research summaries do not cover could not be checked against the legacy text (GAP-11).
- **Classifications:** DONE/VERIFIED, PARTIAL, MISSING, BUG, INTENTIONAL CHANGE, CLIENT CONFIRMATION, UNVERIFIED.
- **Priorities:** CRITICAL, HIGH, MEDIUM, LOW. No finding was rated CRITICAL.

## Summary

- The legacy facts were carried over faithfully:
  - 5 companies with all registration numbers;
  - the complete department directory;
  - the history with historical labels;
  - 4 product groups + UPPZ;
  - the EU project page verbatim;
  - the job offer with pay.

  No fact was lost; one access path was (original certificate PDFs, GAP-01).
- **Certificates have no critical error.** AA+ and 98,60 % are attributed only to the cutting plant (CP) and match the 2026 PDFs. Status is computed from the validity date. SH, SH II and EKO are never shown as current.
- **Launch blockers are legal and configuration items, not technical ones:**
  - privacy policy (GAP-16, GAP-17, GAP-18);
  - form recipients (C-25);
  - staff consent (C-26);
  - tax strategy for 2024 (C-38).
- **Code issues are small:**
  - build-time sitemap/robots origin (GAP-23);
  - the /jakosc meta description (GAP-05);
  - the contact router without JS (GAP-10);
  - minor UX items.

### Certificates, content and maintenance

**GAP-01 · HIGH · Certificates · INTENTIONAL CHANGE (decision needed)**
- **Research:**
  - 01: "KEEP all PDFs as downloadable archive";
  - 06 §20 lists "publishing the full certificate archive as original PDFs" among things not to change;
  - 06 §15: contextual CTA "Pobierz certyfikat (PDF)".
- **Repository:** PL/EN/DE open the WEBP scan in the on-site viewer. None of the 42 pages links to `/documents/certificates/`; the 61 PDFs are reachable only through the legacy 308 redirects.
- **Evidence:** `src/components/certificates/CertificateStatus.tsx:88` ("…no longer the visitor's path"); `CertificateViewer.tsx:34` ("visitors never land on a PDF").
- **Change:** a PDF link for each language next to the preview, for current and archived certificates. **Client:** no. **Effort:** small.

**GAP-02 · MEDIUM · Content maintenance · PARTIAL**
- **Research:** 06 §19: easy editing for the client (staff list, jobs and certificates change often).
- **Repository:** content lives in TypeScript (`src/content/*`), so every change needs a developer and a deployment. A new certificate also needs the scan import scripts, which need the absent `../source-assets` (STATUS, Known issues 4).
- **Change:** decide between a CMS and a documented update procedure. **Client:** yes (decision). **Effort:** large (CMS) / small (procedure).

**GAP-03 · LOW · Certificates · MISSING**
- **Research:** 06 §10: show how to verify certificates.
- **Repository:** the page names BRCGS Directory and the IFS database but not the identifiers to search for. The 2026 PDFs print BRCGS Site Code 1906989 and IFS COID 26277, so these are documented numbers, not new claims.
- **Change:** show both next to the current certificates. **Client:** no. **Effort:** small.

### SEO, Core Web Vitals and performance

**GAP-23 · MEDIUM · SEO / deployment · BUG (latent, deployment-dependent)**
- **Repository:** `sitemap.xml` and `robots.txt` are prerendered at build time (build output `○ /robots.txt`, `○ /sitemap.xml`), while canonical URLs are computed per request.
- **Evidence:** a local production server started with `NEXT_PUBLIC_SITE_URL=http://localhost:5055`, after a build without the variable, served sitemap and robots with `http://localhost:3000`, while the canonical used 5055 (`src/app/sitemap.ts`, `src/app/robots.ts`). The deployment checklist (`security.md` §10) does not say the variable is needed at build time.
- **Change:** render both dynamically or fail the build without the variable; add it to the checklist. **Effort:** small.

**GAP-24 · MEDIUM · Core Web Vitals · UNVERIFIED (unstable test)**
- **Repository:** `npm run test:home` failed one check on the dev server (LCP element `hero__video` instead of `hero__poster`, `tests/home-browser.mjs:77`) and passed fully on a local production build.
- **Why:** the poster stays the LCP element only if the video's first frame is painted before the video grows over the 1 px hairline. In the field, LCP could be recorded at the first video frame.
- **Change:** make sure the video never paints a larger area than the poster; re-run on dev and production. **Effort:** small/medium.

**GAP-25 · MEDIUM · Performance · INTENTIONAL CHANGE**
- **Research:** 06 §18.7: "video not loaded on mobile data by default".
- **Repository:** the hero video loads on the first visit (9.54 MiB desktop, 3.20 MiB phone), except under reduced motion, Save-Data and 2G/3G (`src/components/ui/HeroVideo.tsx:37`). Safari and Firefox do not expose `navigator.connection`, so iPhones always load it. Deliberate quality choice (HERO-003; STATUS, Known issues 7).
- **Change (optional):** poster only on narrow screens, or start on interaction. **Client:** no (the user's decision). **Effort:** small.

**GAP-26 · LOW · SEO · PARTIAL**
- Five meta descriptions exceed 160 characters: PL /jakosc (163) and /zaklady (162); DE home (182) and /de/standorte (173); EN /en/plants (164).
- **Change:** shorten. **Effort:** small.
